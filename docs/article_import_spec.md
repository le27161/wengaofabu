# 规格：文稿批量导入（Excel）

## Objective（目标）

支持用户上传符合固定格式的 Excel（封面图 / 标题 / 栏目分类 / 正文 四列），批量创建文稿草稿，减少逐篇录入成本。

典型场景：从外部抓取整理的新闻稿 Excel 一键导入本系统。

## Excel 格式约定

| 列 | 表头（容错识别） | 说明 |
| --- | --- | --- |
| A | 封面 / 封面图 / 图片 | 图片 URL；为空或无法下载时封面留空（文稿仍导入） |
| B | 标题 | 必填；与库内已存在标题重复则跳过该行 |
| C | 分类 / 栏目 | 按名称匹配栏目，支持顿号/逗号/斜杠分隔多栏目；匹配不到则忽略该分类并提示 |
| D | 正文 / 内容 | 必填；按换行转 `<p>` 段落存入 content，纯文本存入 content_source |

- 仅支持 `.xlsx`（openpyxl），单文件 ≤ 5MB、最多 500 行数据。
- 第一行为表头，其余为数据；全空行自动跳过。

## 封面图处理

- 封面为空：不下载，`cover_url` 留空。
- 封面为 URL：仅允许 http/https，下载限制 20MB 且仅图片类型（jpg/png/gif/webp/svg），按现有存储配置（本地或 OSS）保存。
- 下载失败 / 非图片 / 超时：**该行文稿仍导入**，封面留空，结果中记录"封面下载失败"提示。

## 接口契约

`POST /api/articles/import`（编辑/管理员，multipart 上传字段名 `file`）

响应：

```json
{
  "message": "导入完成：成功 50，跳过 0，失败 0",
  "total": 50,
  "imported": 50,
  "skipped": [],
  "failed": []
}
```

- `skipped`：`[{ "row": 3, "reason": "标题已存在" }]`
- `failed`：`[{ "row": 5, "reason": "标题为空" }]`
- 导入的文稿状态为 `draft`（草稿），作者为当前用户，不自动提交审核。

## 校验规则

1. 文件必须是 `.xlsx`，否则 400。
2. 表头必须能识别出「标题」「正文」列，否则 400（列不匹配）。
3. 标题为空 → 该行失败；正文为空 → 该行失败。
4. 标题与库内已存在文稿重复 → 跳过（不覆盖）。
5. 分类匹配栏目：按栏目名称精确匹配（去空白），多栏目用分隔符拆分；匹配不到的忽略并在结果中提示（不阻断导入）。

## 后端实现

- `services/storage_service.py`：从 resources.py 抽出通用保存函数 `save_bytes(oss_cfg, data, content_type, ext)`（本地/OSS 分流），资源上传与导入封面共用。
- `services/article_import_service.py`：解析 Excel（openpyxl 只读模式）、逐行校验、封面下载、创建草稿，返回统计结果。
- 导入端点使用普通同步 `def`（FastAPI 自动线程池执行），内部 httpx/oss 同步调用不阻塞事件循环。
- `requirements.txt` 新增 `openpyxl`。

## 前端设计（文稿管理页）

- 工具栏「写新文稿」旁新增「批量导入」按钮。
- 弹窗：拖拽/选择 `.xlsx` 上传，说明格式（四列：封面/标题/分类/正文，仅 xlsx、≤5MB、≤500 行）。
- 上传完成显示结果：成功/跳过/失败数量；跳过与失败明细（行号 + 原因）可展开查看。
- 完成后刷新文稿列表（草稿可见）。

## 成功标准

1. 用项目根目录《游戏新闻50篇.xlsx》解析验证：50 行全部识别，栏目"游戏"映射到 game，15 行无封面正常导入且封面留空。
2. 冒烟测试覆盖：正常导入、标题重复跳过、分类不匹配提示、封面 URL 失效不阻断、非 xlsx 拒绝。
3. 前端构建通过；DOM 审核导入弹窗与结果展示；控制台无错误。

## 边界

- Always：行级校验不因单行错误中断全部；封面失败不阻断文稿；中文提示与注释。
- Never：导入覆盖已有文稿；把不可读封面当作整行失败；无权限用户导入。
