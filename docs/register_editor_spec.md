# 规格：注册成为编辑的开关控制

## Objective（目标）

管理员可在后台「门户设置」控制"用户注册时选择成为编辑写手"的开关：

- 开启（默认）：注册页保留"编辑（可写稿）"选项，用户可直接注册为编辑。
- 关闭：注册页不再提供/禁用编辑选项，编辑账号只能由系统管理员在后台创建。

## 配置存储

复用 `system_settings` 键值对（与 `portal_theme`、`site_grayscale` 同模式）：

| config_key | value_type | 默认值 | 说明 |
| --- | --- | --- | --- |
| register_editor_enabled | bool | true | 允许用户注册为编辑写手；关闭后编辑账号仅可后台创建 |

> 说明：配置存 system_settings，但开关 UI 只放在后台「门户设置」页（与灰度开关同模式：设置存在系统配置里，管理入口在门户设置页）。

## 接口契约

### 1. 查询注册策略（公开）

`GET /api/portal/register-editor` → `{ "enabled": true }`

注册页加载时读取，决定是否展示"编辑（可写稿）"选项。

### 2. 更新注册策略（管理员）

`PUT /api/portal/register-editor`，body：`{ "enabled": false }`

门户设置页开关保存时调用。

### 3. 注册接口校验（auth.py）

`POST /api/auth/register`：当 `role == "editor"` 且开关关闭时返回 400「编辑注册已关闭，编辑账号需由管理员在后台创建」。普通用户注册不受影响。

## 前端设计

### 注册页（RegisterView）

- 挂载时拉取注册策略。
- 关闭时：隐藏"编辑（可写稿）"单选（仅保留"普通用户"），副标题改为"当前仅开放普通用户注册，编辑账号请联系管理员开通"。
- 若用户已选编辑后开关关闭（理论上不会发生，防御处理），自动回退为普通用户。

### 门户设置页（PortalManageView）

在"站内公告"之后新增 panel「注册开放配置」：

- 标题 + 开关「允许用户注册为编辑写手」+ 说明文本（关闭后编辑账号仅可后台创建）。
- 开关变更即保存（与轮播/公告启用开关一致）。

## 成功标准

1. 默认开启：注册页显示编辑选项，注册编辑成功。
2. 后台关闭后：注册页编辑选项消失，提交编辑注册被后端拒绝；普通用户注册正常。
3. 后台重新开启后恢复。
4. 冒烟测试覆盖开关关闭/开启两种注册行为；前端构建通过；浏览器 DOM 审核验证注册页与门户设置页。

## 边界

- Always：后端注册接口做最终校验（前端隐藏不等于安全边界）、中文注释。
- Never：关闭开关后仍可通过伪造请求注册编辑。
